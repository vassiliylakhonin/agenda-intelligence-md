Identity basis: SHA-256 of sanitized canonical remote `https://github.com/vassiliylakhonin/agenda-intelligence-md` (HTTPS, no credentials/query/fragment or trailing `.git`).  
Scope: owned repository, including conditional deployment, publication and escrow surfaces. Independent source-backed architecture review; preparation for future scans, not a completed vulnerability audit. Existing unrelated untracked materials were not evidence. No application execution, network contact or deployed-state inspection informed this model. Subsequent Docker runtime verification is separate work and cannot establish production deployment.

## 1. Overview

Agenda Intelligence MD primarily validates claim-backed evidence packets and exposes compatibility strategic-risk services. Callers supply claims, excerpts, quotes and structured requests; deterministic code evaluates structure, evidence references and readiness. Optional model completion, name screening and hosted commerce add materially different boundaries. A favorable score does not establish factual truth or permission to act.

## 2. Threat Model, Trust Boundaries, and Assumptions

Protect evidence integrity, caller confidentiality, service capacity, entitlement balances, payment recovery, continuation capabilities, private signing keys, actual action authority, escrowed value and release integrity. Preserve separate outcome, evidence, limitation and human-review channels. High-stakes human review remains required independently of toolkit output (`SECURITY.md:28`).

A remote caller initially controls submitted JSON/text and ordinary headers, not production secrets, wallet signatures, another task's capability, signing keys or operator credentials. A malicious document/upstream response can manipulate data presented to an evaluator; it does not inherit deployment or action authority. Local CLI/MCP clients share the launching account's authority: do not invent isolation from that same account.

Parsing crosses an untrusted-input boundary: HTTP requires object JSON and caps body length at 1,000,000 bytes (`src/agenda_intelligence/http_api.py:26`, `src/agenda_intelligence/http_api.py:304-327`); Worker parsing streams up to 1 MiB and rejects invalid UTF-8 (`deploy/cloudflare-worker/src/request-body.js:2`, `deploy/cloudflare-worker/src/request-body.js:48-84`). Stdio parsing has different host/resource assumptions. Prompt-injection discipline is policy, not proof of complete resistance (`AGENTS.md:87-92`).

Admission controls remain distinct. Optional production authentication does not replace payment validation. Legacy KV free quotas fail open; Pro quota is a D1 atomic update and fails closed on unavailable entitlement storage (`deploy/cloudflare-worker/src/index.js:924-962`). Trials require Cloudflare connecting-address metadata and D1; caller labels do not create allowances (`deploy/cloudflare-worker/src/output-trial.js:41-102`). Production task ownership uses a capability when configured. A receipt authenticates a bounded evaluation and expressly does not authorize execution. Actual dispatch additionally depends on trusted context, policy, human approval and protected persistent replay state (`src/agenda_intelligence/action_gate.py:196-239`).

Conditional escrow authority is separate: the contract verifies an arbiter signature over escrow/payout/nonce/chain/contract identity, conserves balance and records ruling execution (`contracts/M2MEscrow.sol:236-295`). The relayer currently prepares calldata; its introductory monitoring/broadcasting description exceeds demonstrated implementation (`scripts/base_escrow_relayer.py:2-6`, `scripts/base_escrow_relayer.py:110-175`).

Retain these established discrepancies and unknowns:

- AGENTS calls HTTP “no auth opinion,” while implemented optional keys/CORS/admin/rate policy exists (`AGENTS.md:11`; `src/agenda_intelligence/http_access.py:56-154`).
- Broad no-retrieval/no-billing statements describe a narrower identity than conditional Python retrieval and hosted payments (`AGENTS.md:23-26`; resource rows above). The current security policy explicitly includes these shipped conditional surfaces and distinguishes non-goals from integration boundaries (`SECURITY.md:9-11`, `SECURITY.md:22-30`).
- Wrangler open/free-demo comments coexist with pay_per_call, rate/trial and task-capability settings (`deploy/cloudflare-worker/wrangler.toml:37-55`, `deploy/cloudflare-worker/wrangler.toml:89-116`, `deploy/cloudflare-worker/wrangler.toml:159-185`).
- Task-label comments are historical; the flag-controlled capability branch owns effective production behavior (`deploy/cloudflare-worker/src/index.js:12654-12685`).
- Named GitHub environments do not prove required reviewers. Administrator-held Cloudflare credentials can bypass repository wrappers; deployment checking explicitly detects, rather than prevents, direct Wrangler drift (`deploy/cloudflare-worker/scripts/deploy-all.js:9-15`).
- Actual deployed secrets, bindings, ingress/TLS, telemetry retention outside code, external service implementations and registry permissions remain unverified. External repositories are outside scope; vendored dependency code is a dependency context, not an independent upstream audit.

## 4. Severity Calibration (Critical, High, Medium, Low)

**Critical:** Reserve for an independently established path to broad operator/signing compromise, widespread trusted package replacement, or systemic escrow theft with realistic prerequisites. A malicious evidence paragraph or caller controlling its own host does not establish this impact.

**High:** Plausible examples are unauthorized privileged dispatch, cross-caller confidential result disclosure, meaningful reusable paid-entitlement theft or escrow payout bypass. Require a real sink and new authority; possession of an administrator token or arbiter key changes the starting position substantially.

**Medium:** Bounded service/budget exhaustion, material evidence-integrity failure under the documented contract, or limited operational-data exposure may qualify when reachability and impact are established. Distinguish D1-paid/trial enforcement from the documented fail-open free quota and deployment prerequisites.

**Low:** Limited metadata exposure, narrow hardening gaps or low-impact contract deviations may qualify. Documentation discrepancies alone are not automatically vulnerabilities. An unsigned optional card, local self-only file access, deliberately open local HTTP mode or lack of factual-truth verification is not sufficient without a violated enforceable invariant.

Confidence follows source completeness and verified dataflow; severity follows impact and prerequisites. Preserve unresolved deployment questions instead of converting assumptions into findings, and do not interpret this architecture preparation as evidence that any hypothesis is present or absent.
