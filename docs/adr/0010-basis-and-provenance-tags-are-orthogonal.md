# Schema `basis` enum and SKILL Axis A/B tags are orthogonal, both required

The `basis` enum in `agenda-memo.schema.json` (`fact` / `assessment` / `assumption` / `unknown`) and the SKILL Axis A provenance tags in `skills/agenda-intelligence/references/evidence-discipline.md` (`[primary]` / `[secondary]` / `[user-provided]` / `[inference]` / `[analyst-judgment]`) are not redundant or competing vocabularies. `basis` describes the **epistemological status** of a claim — fact, judgment, working premise, or open question. Axis A describes the **provenance** of the claim — where it came from. They answer different questions and must both be produced. Axis B (`[verify]`, `[stale-risk: YYYY-MM]`) is an additional set of action flags layered on top of Axis A, also not in `basis`.

Two consecutive agent-evals (`evals/agent-eval/gtta-global-policy.md`, plus the first vertical-specialist run) showed the model emitting `basis` correctly in structured output while omitting Axis A tags in the markdown body. The failure is not a vocabulary conflict, so the fix is not a schema migration. The structured `basis` field stays as-is. The runtime contract (`skills/agenda-intelligence/SKILL.md` and `references/evidence-discipline.md`) is the authoritative place to require Axis A inline tags alongside `basis`, and to provide a crosswalk: `basis=fact` typically pairs with `[primary]` or `[secondary]` or `[user-provided]`; `basis=assessment` with `[analyst-judgment]` or `[inference]`; `basis=assumption` with `[analyst-judgment]`; `basis=unknown` carries no provenance tag (no claim is being made). This is documentation, not a schema change — no eval regeneration required.
