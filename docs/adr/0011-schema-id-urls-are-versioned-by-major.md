# Schema `$id` URLs carry the major version, not just the repo path

Starting with v1.0, every JSON schema in `schemas/` (and its packaged copy under `src/agenda_intelligence/data/schemas/`) declares its `$id` as `https://github.com/vassiliylakhonin/agenda-intelligence-md/schemas/v1/<name>.schema.json`. The major-version segment is part of the identifier, not a route. A future v2 that breaks any schema in a way that ADR 0003 classifies as a compatibility surface change — removed enum value, renamed required field, narrowed type, restructured required object — ships under `/v2/` while `/v1/` continues to identify the v1.0 contract unchanged. Minor and patch releases that only add optional fields, add enum values, or relax constraints stay on the same `/v1/` URL.

The decision is made now, while the cost is zero. The current flat `$id` URLs (`/schemas/<name>.schema.json`) have no external consumers: a grep across the local Agenda Intelligence portfolio finds zero references outside the in-repo schema files and their dual-copy mirror. The repo is pre-1.0 (manifest version `0.9.2`). Introducing `/v1/` retroactively after external consumers exist would force every consumer to migrate URLs or force this repo to maintain redirect logic at the GitHub raw layer — both expensive. Doing it as part of the v1.0 freeze costs one mechanical rewrite of nine `$id` strings plus their dual-copy mirror, no consumer impact.

The major-version segment is a stable identifier, not a routing claim. GitHub raw URLs follow the repository tree, so `/v1/<name>.schema.json` requires the schema files to physically live under `schemas/v1/` and `src/agenda_intelligence/data/schemas/v1/`. Cross-schema `$ref` links use relative paths within the same major-version directory so a future `/v2/` tree can evolve without touching `/v1/`. The agent manifest (see ADR 0013) records `schema_version: "v1"` alongside each schema entry to make the contract explicit in the registry, not implicit in URL parsing. Compatibility surface boundaries — what constitutes a breaking change requiring a `/v2/` — are governed by ADR 0003; this ADR only fixes how the identifier expresses the boundary.
