# Middle Corridor & Caspian Research Desk

Status: implemented and locally tested; production activation approved by the owner on 2026-10-27; live verification pending.

The server collects named primary-source pages and produces a dated research draft. The client
supplies a question, not the source packet or a completed analysis. Existing evidence-verification
tools remain separate. This is an experimental research draft, not a factuality certificate or
legal, investment, operational or sanctions advice. Human review is required.

## Interface

- Browser: `/research` on the top-level Agenda host.
- Discovery and source catalog: `/.well-known/corridor-research.json`.
- Stateless Streamable HTTP MCP: `/v1/research/mcp`, with `research_brief` and `get_research`.
  `/mcp/research` remains an application alias; use the canonical `/v1/` address for ordinary
  machine clients because the existing zone's BIC exception covers that API namespace.
- REST: `POST /v1/research`, then `GET /v1/research/{research_id}`.
- Contracts: [request](../../schemas/v1/corridor-research-request.schema.json) and
  [response](../../schemas/v1/corridor-research-response.schema.json).

Use a private random caller capability in `Authorization: Bearer <token>` for creation and polling.
It is generated by the caller and is not a provider API key or an execution grant. No registration
is required. The server stores its digest only. Anyone holding it can read that caller's jobs;
keep it out of URLs, public logs and source documents. The browser generates it automatically and
keeps it in tab session storage, with a memory-only fallback. Losing it loses access to the job.

Create a unique `request_id` for a new research run. Retry an uncertain submission with the same
capability, request ID and body. This returns the existing job without making another model call.
The browser retains the pending request key even after acknowledgment, so submitting unchanged
input reuses that job. Its **Start a fresh run** button, or a new explicit API request ID, creates
a fresh run and consumes allowance.

Example (after production activation):

```sh
RESEARCH_TOKEN=$(openssl rand -hex 32)
curl https://agendamcp.dpdns.org/v1/research \
  -H "Authorization: Bearer $RESEARCH_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"question":"What changed on the Aktau–Alat–Poti route?","language":"en","lookback_days":30,"request_id":"my-first-research-20261027"}'
```

The create response is HTTP 202 with a private `research_id` and status. Poll the ID with the same
bearer capability. States are `queued`, `collecting`, `analysing`, `completed`, or `failed`.
Discovery and polling never invoke a model. New research does not change or authorize a real
shipment, publish a document, contact an operator or initiate a financial action.

## What is collected

The catalog contains TITR Association, World Bank, CAREC Institute and EDB institutional/operator
pages. The collector reads a fixed index/report per institution and may follow a relevant same-host
article. HTTPS hosts and redirects are checked. Responses have byte/time/type bounds. Current
support is HTML/plain text only; PDFs and authenticated data are not read. The service records
source URLs, retrieval/publication dates, text/content hashes, access failures and freshness labels.

Publication and retrieval dates do not establish the observation period or effective date of a
figure. Those fields remain unknown until supported explicitly. A background document is not a
recent event. Search/discovery coverage is bounded, not exhaustive. The initial collector does
not promise current freight quotes, schedules, slots, AIS or shipment tracking.

Retrieved text is untrusted DATA, never instructions. It cannot choose URLs, tools, models,
credentials or actions. The fixed model receives the canonical vendored Agenda and regional
methods and selected source excerpts. Its output must have source IDs and matching quotations.
Reference checks establish neither semantic entailment nor truth. Unsupported quotes, invented
IDs, invalid JSON and excessive quotations fail the research job; they are not reformatted into
an apparent success. Interpretations are labeled separately from source-backed findings.

## Limits and retention

- Five admitted jobs per UTC day globally; two per private caller capability. Limits can be lowered
  by the operator; request bodies cannot raise them. Owner/test markers provide no exemption.
- One model dispatch per job. At most 20,000 prompt bytes and 2,048 output tokens, with the fixed
  `@cf/meta/llama-3.3-70b-instruct-fp8-fast` model.
- At the model's currently published token prices, five maximum-sized runs are estimated below
  USD 0.10/day for model inference. This is an estimate, not a contractual total bill cap; hosting,
  database and Workflow pricing/allocation are separate. No plan change is part of this work.
- Ambiguous inference outcomes become `model_outcome_unknown`. Retrying or replaying that job
  never automatically dispatches a second model request. Start a new run only deliberately.
- Private working source text and raw model output are removed after a terminal outcome, with
  a 24-hour logical expiry and hourly cleanup for interrupted jobs. Completed briefs,
  short quotations and metadata expire after seven days. Cleanup runs on admission and via the
  top-level Worker scheduler; Workflow checkpoints contain only receipts, not source text or raw model output.

## Deployment approval and activation

The owner explicitly approved PR457 resource creation and activation on 2026-10-27 after reviewing
its limits and possible costs. The dedicated D1 database `agenda-corridor-research` was created;
its UUID is configured in Wrangler. The approved scope is one D1 database, one Workflow of the
same name, the Workers AI binding and a Vizier-gated release of the existing Agenda root Worker.
There is no additional domain, account, plan upgrade or paid third-party search API.

Automatic approval review initially refused the persistent resource. It was created only after
explicit owner consent; the refusal was not bypassed and research state does not use the payment ledger.

Activation procedure:
1. Apply only `research-migrations/0001_research.sql` through the dedicated `RESEARCH_DB` binding.
2. Verify `RESEARCH_ENABLED=1`, the five-job global allowance and short Workflow retention.
3. Merge the tested commit. Dispatch the existing **Deploy existing Worker fleet through Vizier**
   workflow from immutable main with `target=agenda-root`; signing bootstrap remains false.
   It mints the usual separate owner grant and requires Vizier ALLOW before deploying only the root Worker.
4. Verify discovery without a model call, then make one owner-marked real research run.
   Send `X-Client-Id: agenda-owner-corridor-research-smoke`; keep the client's normal User-Agent.
5. Check real source access, inference, quotations, private polling, the served draft and global
   allowance. Do not claim a deployed researcher before that succeeds.

## Local verification

```sh
cd deploy/cloudflare-worker
node scripts/generate-research-methods.js --check
node --test test/corridor-research.test.js
npm test
npm run test:research-runtime
npx wrangler deploy --dry-run --env ''
```

The regression suite uses actual SQLite for D1-compatible admission statements, fixture HTTP
sources and a fixture model. It exercises the complete REST/MCP create → execute → poll path,
source failures, redirects, byte bounds, private access, idempotency, concurrent quotas, quote
validation and model-outcome recovery. It does not establish live model quality or production
Cloudflare integration. A separate live collector check can verify official page access without
calling a model. See [ADR 0041](../adr/0041-bounded-server-research.md).

The runtime check uses the pinned Wrangler's local Miniflare/Workerd engine, local D1 and a
fixture RPC model with fixture outbound pages. It exercises the actual production entry and
Workflow class, covers English/Russian jobs with one fixture inference each, checks private REST/MCP access,
verifies the augmented AgentCard signature, and checks working-text cleanup. It makes no live
model call and creates no cloud resource. CI runs it alongside the faster Node regressions.

Requested Russian output must contain Cyrillic in every narrative claim, interpretation and open
question; source quotations remain in their original language. A fully English narrative is
rejected as `model_output_language_mismatch`, rather than labeled Russian. This is a narrow
script-presence check, not a certificate of translation quality or fluency. The requested
language is supplied explicitly after the canonical methods and in the structured model input.
