# First-check client decision workspace

- goal: let an integrator reach one completed supplied-evidence review through connection inspection, raw-argument schema preflight, explicit trial admission and optional completion-bound feedback.
- trusted_evidence: published session MCP handlers, free_trial tools and their actual example arguments, current schema preflight, existing allowance ledger and recent-completion feedback checks.
- suspected_unreliable_evidence: anonymous request labels, raw user/source content, remote error strings and claimed usefulness are unverified data. Invalid-input events do not establish potential buyers or a cause of lost sales.
- hidden_assumptions: a standalone client reduces integration steps. Actual usefulness and reuse still require a person reviewing their authorized material; transport success cannot establish either.
- intended_next_action: publish the canonical dependency-free Node example as a generated Worker download, link existing discovery/recovery, test real offline handlers and marked live probes, and release through existing CI and Vizier-gated deployment.
- stop_or_escalate_if: inspection reserves an attempt, a paid operation or automatic retry is sent, source text becomes instructions, input changes after preparation, feedback lacks a verified completion, owner tests count as external demand, or required checks fail.

Public contract and commands: [first-check guide](../../examples/hosted-mcp/FIRST_CHECK.md).
This is a transport/example surface. Existing schemas, allowances, tariffs,
authentication, result contracts and telemetry classifications apply. The download
is generated from the canonical example and checked by `npm test`.
The download uses `/.well-known/first-check.mjs`, inside the existing fleet's
machine-client edge exception. Owner-marked default urllib probes reached this
prefix before release; a root-path download received Cloudflare error 1010.
No security rule or User-Agent override is needed for the chosen path.

Offline contracts exercise actual wire-discovered arguments on all twelve
profiles, including Financial Guard/Escrow where paid wrappers differ, input
mutation, invalid JSON, exhausted/disabled trials, auth, lost responses,
completion-bound feedback and file failures. Synthetic owner checks establish
tested behavior, not customer usefulness or paid demand.
