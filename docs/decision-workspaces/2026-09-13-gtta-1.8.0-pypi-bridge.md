# Decision workspace: GTTA 1.8.0 PyPI bridge

- **Goal:** publish the already tagged
  `global-think-tank-analyst==1.8.0` distributions to its declared public
  PyPI channel.
- **Trusted evidence:** GTTA commit `80b7d5a` is tagged `v1.8.0`; GitHub CI
  run `34767414612` passed all jobs; tagged release run `34767712577` passed
  tests, repository checks, build, metadata checks, installed-wheel smoke, and
  artifact upload before its direct Trusted Publishing step failed with
  `invalid-publisher`; PyPI returned `404` for version `1.8.0` before this
  bridge was added; the same repository-scoped pattern published GTTA `1.7.0`
  through run `34752106521` and was removed in commit `e980c8e`.
- **Suspected unreliable evidence:** GitHub secrets are write-only, so the
  retained `PYPI_API_TOKEN` cannot be inspected. Its continued validity and
  scope can be established only by the upload result and PyPI readback.
- **Hidden assumptions:** the retained token remains account-scoped and can
  publish the existing GTTA project, as it did for `1.7.0`.
- **Intended next action:** manually dispatch the one-use workflow for
  `v1.8.0`; it checks exact tag SHA, project name and version, refuses an
  existing PyPI version, repeats tests and release checks, builds from the tag,
  smoke-tests the wheel, and uploads with the retained token.
- **Stop or escalate if:** source identity or metadata differs; any gate fails;
  PyPI already contains `1.8.0`; the token is rejected; or the post-upload
  clean install does not report GTTA `1.8.0` with Agenda Intelligence `1.9.0`.
- **Cleanup:** after PyPI JSON and clean-install verification, delete the
  temporary workflow. Retain this record as the audit trail; do not retain a
  standing cross-project publication path.
